## A real bug: rehome (ec56ebc9)

The old `rehome` called `setParent(parentWidget())`. When the parent was a
widget only C++ made (for example the tab container inside QtAds), its
Python wrapper was a throwaway. That wrapper died right after the call, and
it took the rehomed wrapper with it. A Tab walk over a QtAds tab crashed
natively.

- New rule: rehome first files each parent made only by C++, going up until
  it reaches a wrapper Python made.
- It never takes ownership of a host window with no parent, because
  deleting the wrapper would then delete Houdini's main window.
- New test: `test_rehome_never_files_a_wrapper_under_one_about_to_go`. It
  fails on the old code.
- The same bug caused the "hidden start" crash. ls's own pane-close test
  passes without that guard once fxgui's new rehome is swapped in at
  runtime (4 of 4). So the guard is removed: the fix is in rehome, where
  the cause was.
- Tested the other way too: with the old rehome put back, the fxgui
  pane-close test crashes.

## Public API

`fxgui/fxdocking.py`. Importing it imports PySide6QtAds. Nothing else in
fxgui imports it; `tests/test_fxdocking_optional.py` checks that.

- `class FXDockArea(QWidget)`
  - `__init__(parent=None, gap=6)`
  - `manager() -> CDockManager`
  - `set_central(widget)`
  - `add_dock(name, title, widget, area, *, beside="", size=(1, 1),
    tab_with="") -> QAction`, the pane's toggle. Raises `ValueError` for an
    unknown area, or when no pane has the `beside` or `tab_with` name.
  - `show_dock(name)`: also raises a floating pane's window.
  - `set_dock_title(name, title)`
  - `set_dock_tip(name, tip)`
  - `keep_panes_open()`: applies again after every restore and reset.
  - `save_state() -> bytes`
  - `restore_state(state) -> bool`: False when `restorable()` refuses.
    Before the first show the layout waits, and is applied after the split
    is sized.
  - `reset_layout()`
  - `clear_top(width, height) -> int`
  - `focusNextPrevChild`: the declared Tab walk.
  - A floating pane gets the window's own actions (`window.actions()` and
    every `WindowShortcut` action) plus its `QShortcut`s.
- `restorable(state: bytes, built: bytes) -> bool`
- `banner_host(widget) -> QWidget`: the FXDockArea of the app window, even
  from a floating pane; without one, the widget's window.

`fxgui/fxutils.py`: `later(ms, owner, call)`, `rehome(widget)`,
`focus_step(widget, forward=True)`, all in `__all__`. They are defined once,
in `fxgui/_compat.py`, and fxutils re-exports them. A test checks that each
fxutils name is the `_compat` object.

`pyproject.toml`: `docking = ["PySide6-QtAds"]`. `fxgui/__init__.py` is
untouched: adding fxdocking there would import QtAds.

## Changes from the ls version, each with a test

1. The QtAds sheet is registered through `register_widget_style`, with
   every rule under `#fxDocks` (the manager's objectName). Without the id,
   the base sheet's `QFrame[frameShape="0"]` rule wins over a plain
   `ads--X` selector, and the cards lose their border and round corners.
2. The Tab walk is on FXDockArea, so it runs only while focus is inside the
   panes. ls's 7 keyboard suites (451 tests) pass with ls's walk limited
   this way, applied at runtime.
3. Why the walk is needed: Qt's own walk stops at a widget whose focus
   proxy sits elsewhere in the chain (an FXSearchBar), and jumps to that
   proxy. New test `test_tab_passes_a_widget_whose_focus_goes_elsewhere`
   fails without the override. The ls hub test
   `test_tab_walks_the_declared_order` also fails without it.
4. Button icons are registered once, as copies. fxicons now draws theme
   tokens, so a theme switch needs no new icons. A theme change still
   recolours the drop-target crosses and refits the tab bars.
5. Pane sizes and sides live in dicts on FXDockArea, not in `ls_*`
   properties.

Mutation checks: removing the icon copy, the side-bar check, the keep-open
reapply, or the float key copy each makes a test fail. The keep-open after
restore case had no test, so
`test_a_kept_pane_closed_in_a_layout_restored_after_the_show_opens` was
added.
