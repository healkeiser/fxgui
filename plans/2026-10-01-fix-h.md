6.5.3 CRASH (product fix, outside tests/)

On PySide6 6.5.3, after any themed root is registered, typing an `@` in
FXMentionEdit crashed the process (access violation in
`completer.popup()`). It reproduces outside pytest. Cause: the app-wide
focus filter asks the completer's list `parentWidget()` when it shows.
On 6.5.3, asking a parentless widget that C++ made for its parent hands
it to Python; when the filter's wrapper goes, Python frees the list, and
the completer keeps a dead pointer. 6.11 does not do this. Measured:
`ownedByPython(popup)` is False before the call, True after.

Fix: `_compat.parent_widget(widget)` asks the parent and, when the answer
is None for a widget C++ made, holds the wrapper until C++ frees the
widget. Every parent walk on a widget that may be C++-made goes through
it: fxstyle.py `_dress_popup` (2 calls) and `_is_themed`, fxutils.py
`_file_back`, fxdocking.py `banner_host`. The last two walk up to a
host's own window, which on 6.5.3 the same call would hand to Python.
Test: test_comments.py::test_a_name_list_outlives_the_theme_looking_at_it
crashes on 6.5.3 before the fix and passes after; it passes on latest
either way. test_package_layout's `_compat.__all__` list names the new
shim.
