# Timing and Houdini proofs (13.0.0, branch audit-fixes)

Machine: this Windows 11 desktop. 13.0.0 = audit-fixes at 4e484632 (the
fixes below included). 12.x = tag v12.12.0 in its own worktree and venvs
(scratchpad `timing/v12`). Scripts: scratchpad `timing/bench.py`,
`timing/hython/*.py`. Every number is milliseconds; a switch is the
median of 10 (dark -> light -> dark, five times), events flushed after.

## 1. Splash: 1 s per show, fixed

Cause, in Qt's `qsplashscreen.cpp`: since Qt 6.7 `QSplashScreen::event`
calls `waitForWidgetMapped(this)` on `QEvent::Show`, which spins up to
1000 ms until `windowHandle()->isVisible()`. Qt sends the Show event
before it maps the native window (`show_helper` sends it, then
`show_sys`), so the wait can never succeed and every show pays the full
timeout. 6.5.3 and 6.6.0 have no such wait.

Fix: `FXSplashScreen.event` sends Show straight to `QWidget.event`,
skipping that wait; Paint and the rest still go through QSplashScreen.
The window is still mapped and exposed when `show()` returns (measured
below), which is all Qt's wait was for.

| Real desktop (`QT_QPA_PLATFORM=windows`) | 6.11.1 | 6.5.3 |
|---|---|---|
| QWidget, first show | 61 | 61 |
| QSplashScreen | 1012 | 7 |
| FXSplashScreen before | 1010 (lead's number) | 400, first show only |
| FXSplashScreen after | 13 (then 7) | 400, then 7 |

The test `test_a_show_costs_what_a_widget_show_costs` failed first
(1.015 s) and passes now; the splash test file went from 4.7 s to 2.5 s.

The 400 ms left on 6.5.3 is not the splash. On Qt 6.5's Windows font
database the first use of any weight other than 400 or 700 costs about
380 ms once per process (a QLabel at Segoe UI 600: 445 ms first show;
at 700: 68 ms; Arial 600: 439 ms). The splash title's `card` rank is
weight 600. 6.11 does not pay it. `-platform windows:fontengine=directwrite`
removes it on 6.5.3 (62 ms), but that is the host application's choice,
and the only 6.5 host is Houdini, whose own UI has paid it already.
Not changed.

Commits: a508ba06 (fix, test), d0fdf231 (comments name 6.7, not 6.6).

## 2. Timing

### Theme switch on the gallery

`fxgui/examples.py` `build()` for 13 (all eight pages); for 12 the same
window its `main()` builds, without the splash. Offscreen, then on the
real desktop.

| Offscreen | widgets | build | show | switch (median) | worst |
|---|---|---|---|---|---|
| 13.0.0, 6.11.1, before 4e484632 | 720 | 448 | 23 | 321 | 359 |
| 13.0.0, 6.11.1 | 720 | 406 | 20 | 286 | 333 |
| 13.0.0, 6.5.3 (no QtAds: no docking page) | 617 | 192 | 17 | 218 | 223 |
| 12.12.0, 6.11.1 | 528 | 401 | 42 | 619 | 633 |
| 12.12.0, 6.5.3 | 528 | 402 | 42 | 583 | 623 |

| Real desktop | build | show | switch (median) |
|---|---|---|---|
| 13.0.0, 6.11.1 (before 4e484632) | 916 | 92 | 304 |
| 13.0.0, 6.5.3 (before 4e484632) | 593 | 106 | 235 |
| 12.12.0, 6.11.1 | 553 | 539 | 639 |
| 12.12.0, 6.5.3 | 546 | 454 | 640 |

13 switches about twice as fast as 12 with 36% more widgets. Of a 13
switch, 75% is inside Qt's `QApplication.setStyleSheet` repolishing
each widget (about 0.38 ms a widget; the sheet itself costs 10 ms to
set on an empty app, 54 kB, 322 rules). The next cost was fxgui's own:
the one application-wide focus filter (`fxstyle._FocusVisibility`) ran
its whole `elif` chain on all 18,500 events a switch sends. It now
leaves at once on any event type it does not watch: 321 -> 286 ms
offscreen, and the gallery builds 40 ms faster. Every event the app
handles, not only a switch, now pays one set lookup there.
Commit 4e484632.

### Icon draws

1000 distinct material icons, `get_icon(name).pixmap(size)`, in a fresh
process per size. Cold = first pass, warm = the same 1000 again.

| | 16 px cold / warm | 24 px cold / warm | 32 px cold / warm |
|---|---|---|---|
| 13.0.0, 6.11.1 | 185 / 30 | 174 / 28 | 199 / 32 |
| 13.0.0, 6.5.3 | 172 / 31 | 164 / 30 | 188 / 32 |
| 12.12.0, 6.11.1 | 309 / 286 | 308 / 293 | 297 / 291 |
| 12.12.0, 6.5.3 | 285 / 263 | 289 / 272 | 283 / 268 |

12's `lru_cache(maxsize=512)` cannot hold 1000 icons, so its warm pass is
cold again; 13's QPixmapCache holds them (10x faster warm).

### Theme switch with 500 icons on screen

| | 500 items in an icon-mode list | 500 tool buttons via `set_icon` |
|---|---|---|
| 13.0.0, 6.11.1 | 27 (worst 76) | 60 (worst 131) |
| 13.0.0, 6.5.3 | 25 (worst 69) | 59 (worst 124) |
| 12.12.0, 6.11.1 | 21 (worst 24) | 294 (worst 333) |
| 12.12.0, 6.5.3 | 20 (worst 22) | 294 (worst 317) |

The list is the only 13 number above 12's, by 6 ms, and it is not a
defect: 12's `get_icon` icons never follow a switch, so 12 redraws
nothing; 13 redraws every visible icon in the new ink. The worst case
is the first switch, when each visible icon is drawn once in the new
ink before the cache holds it. `set_icon` buttons, the path both
versions recolour, are five times faster in 13.

## 3. Houdini proofs (hython, offscreen, no GUI launch)

Command, per version and proof, from scratchpad `timing/hython`:

    bash run.sh <21|22> proof_<name>.py

`run.sh` sets `HFS`, `QT_QPA_PLATFORM=offscreen`,
`QT_QPA_FONTDIR=C:/Windows/Fonts`, and `PYTHONPATH` = the worktree, QtPy
2.4.3 (rez, development), `houdini_qtads` 5.0.0.2 (the variant for that
Houdini), and for Houdini 22 PyYAML 6.0.3 cp313 (hython 22 ships no
yaml). Each proof installs a Qt message handler and fails on any Qt
warning; the full output was also searched for "already deleted",
"Fatal", "access violation" and "RuntimeError" (none). The traceback
hython 21 prints about NumPy 1.x/2.x on PySide6 import is Houdini's own.

| Proof | Houdini 21.0.631 (PySide6 6.5.3) | Houdini 22.0.368 (PySide6 6.8.3) |
|---|---|---|
| fxdocking | OK, exit 0 | OK, exit 0 |
| clone shutdown | OK, exit 0 | OK, exit 0 |
| host rules | OK, exit 0 | OK, exit 0 |
| 150% render | OK, exit 0 | OK, exit 0 |

- **fxdocking** (`proof_docking.py`): an FXDockArea in a themed
  QMainWindow, three panes docked (left, bottom, right), one floated
  with `setFloating()`, one closed with `toggleView(False)`. Checked:
  three open and docked, one floating, one closed; dark -> light -> dark
  -> light; `restore_state(save_state())` taken and the float still
  floats; close + deleteLater leaves no CFloatingDockContainer. No Qt
  message at all.
- **Clone shutdown** (`proof_clones.py`): 20 `get_icon` icons copied and
  `addPixmap`-ed (which clones the engine), set on buttons, a switch,
  then the interpreter exits with all of them alive. `_clones` held
  them, a clone still draws, exit code 0, no crash.
- **Host rules** (`proof_host.py`): a plain QApplication (fxgui does
  not theme it, so it is a host as fxstyle sees one: `_in_host` is
  "the app is not a themed root"), a host QMainWindow wearing the
  install's real `base.qss` (tokens filled as `test_host_sheet` does),
  an FXMainWindow parented to it. Checked before and after a switch:
  the window is a themed root, the app is not; the window's sheet
  starts with `_host_rules()`; the app's sheet and palette are
  unchanged; the window's Window colour is the theme `surface` and a
  label's ink the theme `text`.
- **150% render** (`QT_SCALE_FACTOR=1.5 bash run.sh <v> proof_render150.py <out>`):
  an FXMainWindow with tabs, a button with an icon, line edit, combo,
  spin box, check box, slider and a list with an icon row and a
  selection, 520 x 560, grabbed at ratio 1.5 (780 x 840 px), dark and
  light. Looked at all four PNGs and zoomed into the icons and arrows:
  icons and chevrons are drawn at 1.5, sharp, not upscaled; text, edges
  and the selection pill are clean in both themes and both Houdinis.
  Nothing wrong found. (The spin box puts its down arrow left and up
  arrow right; that is the sheet's design, `subcontrol-position` in
  style.qss, not a 150% fault.)

No proof failed, so no fix came from this part.
