OWNER BUG: windows flashing while the gallery builds

Cause: a widget made with no parent and then given `setVisible(True)` or
`show()` before it is added to a layout is a top-level window for that
moment. A test now records every QEvent.Show of an isWindow() widget
during build(), window.show() and one processEvents, and asserts the
gallery window alone shows. Seven windows showed:

| Widget | Where | Fix |
|---|---|---|
| 3 x FXLoadingSpinner | examples.py: `spinner.start()` (start() calls show()) on an unplaced spinner | Done: the gallery starts them after the page is built (ffded17d) |
| QComboBox | _search_bar.py:71 `self._filter_combo.setVisible(show_filter)` before addWidget | Group f: `QComboBox(self)`, or setVisible after addWidget |
| QLabel#fxProgressCardDescription | _progress_card.py:153 setVisible before addWidget | Group e: `QLabel(description or "", self)` or setVisible after addWidget |
| QLabel#FXDropZoneFormats | _drop_zone.py:222/326 `_update_formats_label()` before addWidget | Group g1: `QLabel(self)` or call it after addWidget |
| QWidget (slider container) | _fuzzy_search_list.py:101 setVisible before addWidget | Group c: create with `self` as parent, or setVisible after addWidget |

Also for e: _loading_spinner.py:80 `start()` calls `self.show()`, so any
caller that starts a spinner before placing it opens a window. Consider
dropping the show() or skipping it while `parent() is None`. Each owner
got this message directly.
