_tips.py
- B1 / top bug 3 (tip HTML bakes the old theme's colours): done, and the
  in-progress palette-role fix was not enough. Qt 6.5 rich text has no
  name for the placeholder-text role: on PySide6 6.5.3,
  `palette(placeholder-text)` parses as opaque black, so every tip body
  was black on Houdini 21. Measured with a QTextDocument on 6.5.3 and
  6.11.1. Now `tip()` writes the current theme's hex colours, and
  `apply_tip` rebuilds the HTML when the tip shows:
  - a widget: on QEvent.ToolTip, through one shared event filter;
  - a QAction: on `hovered`, which a tool button and a menu send before
    they read the action's tooltip;
  - a QListWidgetItem, QTreeWidgetItem or QTableWidgetItem: the parts sit
    in an item role, and the view's viewport builds the tip on
    QEvent.ToolTip. A tree item gets it on every column. An item in no
    view raises ValueError, because there is no viewport to watch yet.
  - a model: returns `tip(...)` from `data(ToolTipRole)`, which Qt asks
    for on hover, so it is built when it shows with no help.
  Tests: test_a_tip_is_written_in_the_theme_in_force (failed: palette
  roles), test_a_tip_set_in_one_theme_shows_in_the_theme_of_the_moment
  (failed on 6.5.3: body black), test_an_item_tip_is_built_when_it_shows,
  test_an_action_tip_is_built_when_it_is_hovered,
  test_apply_tip_covers_every_column_of_a_tree_item (failed: TypeError,
  QTreeWidgetItem.setToolTip takes a column),
  test_apply_tip_refuses_an_item_in_no_view.
