## Item 11: status items (case 1)

New names:

- `FXStatusItem(text="", icon=None, parent=None, clickable=True)`, a
  QToolButton that paints its icon, word and hover fill itself, against
  the bar's colour at paint time.
  - `show_state(text, icon, muted=False, tone="")`
  - `set_clickable(clickable)`: plain items take no mouse.
  - `set_tip(title, body="", keys="")`: tooltip, no status tip.
  - `ground() -> str`, `ink() -> str`, `radius` (= `fxstyle.BUTTON_RADIUS`)
  - Hidden while its text is empty. Icon size 14.
- `FXStatusBar.add_item(item, side="left")`: "left" goes before the

- `FXStatusBar.items() -> list`, `tint() -> Optional[str]`,

- `project_label`, `version_label`, `company_label` are now plain
  FXStatusItems. `project=None` leaves the project blank.
- `FXMainWindow.event` sends every `QStatusTipEvent` to `show_tip`.

## Item 17: command row (case 1)

New name: `FXCommandRow(title="Command row", parent=None, margins=None,
spacing=None, icon_size=17)`, a QToolBar.

- It cannot be moved, cannot float, and has no menu entry to hide it.
- `margins` is (left, top, right, bottom). It holds through style and
  theme changes.
- Qt's horizontal toolbar layout swaps left/top and right/bottom.
  FXCommandRow swaps them back, and I measured this.
- The window's own toolbar is now an FXCommandRow.
- objectName is "fxCommandRow".

Tests: 4 in tests/test_main_window_rows.py.

## Item 18: framed windows flatten icon-only buttons (case 1)

New behaviour: a framed FXMainWindow watches its own bars (toolbars,
status bar, menu bar). An icon-only QPushButton with no fxRole gets
`fxRole="flat"`. This also applies to nested buttons and to buttons
added after show. A role already set is kept.

Tests: 3 in tests/test_main_window_rows.py.

## HOST_RESET (case 1)

New behaviour: `fxstyle._HOST_RULES`, the one prefix for roots inside a
host application, ends with rules that undo what Houdini 21 and 22's
base.qss set and the base sheet leaves open. The QWidget block and
`_host_rules` were not touched. The rules sit in one hunk after the
root block.

Besides ls's set, two resets were needed, both proven by the pixel test:

- `QLineEdit { height: -1px; }`
- `QWidget { margin: 0px; outline: none; }`

No ParentChange or setStyleSheet override is needed. A window registered
inside a host gets the rules whether or not it is parented.

Tests: tests/test_host_sheet.py, 7 tests: the sizes test and the pixel
test, each on the inline rules and on the real base.qss of H21 and H22
read from the installs, plus a test for a window reparented into a host.

The ls test had no fixture files. It reads base.qss from
C:/Program Files/Side Effects Software, and so does the fxgui test. I
did not copy SideFX's file into the repo, because of its licence; on a
machine without Houdini only the inline rules run.

ls replacement:

- `window.py:103-132` comment and HOST_RESET -> delete.
- `window.py:863` `self.setStyleSheet(self.styleSheet())` -> delete.
- `window.py:865-871` setStyleSheet override -> delete.

## scroll_by_pixel (case 1)

New behaviour: in style.qss the `QAbstractItemView` rule sets
`qproperty-verticalScrollMode: ScrollPerPixel` and
`qproperty-horizontalScrollMode: ScrollPerPixel`. The enum name works on
the venv's PySide6, so the integer was never needed. The styleHint
override is gone, and so are the per-view calls in _drop_zone.py and
_fuzzy_search_list.py.

Trade-off, written in docs/how-to/theming.md: a view that wants
ScrollPerItem says so in a rule of its own, by objectName.

Tests: tests/test_smooth_scroll.py. 18 tests, each run in app mode
(fxgui's style plus the app registered as a root, as FXApplication does)
and in host mode (a plain QApplication with one registered root). App
mode needs fxgui's style as well as the sheet: without it, rows are
measured before the sheet styles them, and one notch moved 33px instead
of about three rows.

ls replacement: `widgets/keys.py:43-47` scroll_by_pixel and its 10 call
sites -> delete. A view that must scroll by row gets an objectName rule.
