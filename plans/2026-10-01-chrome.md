### How the chevrons follow the theme

A Qt sheet loads an image only from a file. So `fxstyle` resolves a new
placeholder, `~icon(name, token)`, to a copy of the icon library's SVG
with `fill` set to that token's colour. The copy is written once per
colour to `<tempdir>/fxgui/sheet_icons/`. Every arrow and chevron in
`style.qss` uses it. The old static `stylesheet_dark|light` arrow and
branch SVGs are deleted. Documented in `docs/how-to/theming.md`.

### Item 7 in detail

- The combo box now asks for a list popup (`combobox-popup: 0`). The
  menu-style popup added a tick and indented the current row. It also
  left 4 px strips top and bottom.
- `QComboBox:on` padded the closed combo's text 1 px differently. That
  rule is gone. So is the 1 px jump of `QToolButton::menu-arrow:open`.
- On 6.11, a list's resting row sits 1 px further in than a highlighted
  row. Qt draws the resting row natively. Highlighted list rows get 1 px
  more padding to match. The combo list has no such inset, so it is
  exempt.

### Item 8: the combo popup's frame

Qt's sheet refuses to style `QComboBoxPrivateContainer`. In
qstylesheetstyle.cpp, `unstylable()` returns true for any QFrame whose
parent is a QComboBox. So no rule can reach that frame. The
`QComboBox QFrame` rule the sheet carried never applied, and it is
deleted.

What happens instead:

- The app-wide focus watcher (`_FocusVisibility`) sees every popup's
  `Show`.
- For a combo's popup, it sets the frame to a 1 px Box. The edge is drawn
  in `@border` from the palette.
- The list inside fills the frame square, in `@surface`.
- The watcher calls `fxutils.round_window_corners` on every themed popup
  when it shows: menus, combo lists, completers, calendars, the palette.
  A completer's list has no parent, so the watcher adopts it as a themed
  root while a themed widget holds focus.

### Slider groove: why the span cannot also read 3:1 on it

The groove is `@control_edge`: 3.02:1 to 3.21:1 on `@surface` across the
eleven themes, and 3.02:1 in solarized_light (it was 1.00:1 there).

The span stays `@accent_primary`, at 3.4:1 to 7.8:1 on the surface. Two
colours that both sit 3:1 away from the surface, on the same side of it,
cannot be 3:1 from each other. Their measured ratio is 1.13:1 in
solarized_light and 2.53:1 at best. So the span is told from the groove
by its hue and by the handle at its end. The old test that asked for
span-on-groove 3:1 now asks for groove 3:1 on the surface and span
different from groove.

## Open points

1. **PySide6 6.5.3 (Houdini 21): a row's text still jumps 8 to 9 px on
   hover or selection.** This was already true before this branch. On
   6.5.3 Qt paints a resting row natively and ignores the sheet's
   `padding: 4px 8px`. It honours that padding on a hovered or selected
   row. Measured text start, rest / hover / selected:

   | View | Text start (px) |
   |------|-----------------|
   | List | 3 / 12 / 12 |
   | Tree | 23 / 31 / 31 |
   | Combo list | 8 / 16 / 8 |

   Any rule that makes the sheet draw the resting row (for example
   `border: 0px solid transparent`) fixes the jump. It also hides the
   item's own `BackgroundRole` on both Qt versions, which the base-sheet
   contract keeps. No rule I tried satisfies both. The tries were
   `border: native`, `margin`, `outline` and `:!hover:!selected`
   padding. The way out is a rule gated on the Qt version, like
   `_HOST_RULES`, which gives up `BackgroundRole` on old Qt only.
   I have not measured 6.8.3 (Houdini 22). Needs a ruling. Until then,
   `test_a_view_row_keeps_its_text_still[list/tree]` and
   `test_a_combo_popup_row_keeps_its_text_still` fail in the 6.5.3
   venv: 6 cases, dark and light. Everything else covering this branch
   passes there.
2. The sweep checks the colour that covers most of each part. A small
   unstyled strip inside a widget would still pass. It caught the MDI
   area, the completer popup, the calendar header (which my item 5 had
   broken by dropping `alternate-background-color`) and the menu-style
   combo popup's scroll arrows (gone with item 7).
3. Not backgrounds, so not changed:
   - The QDial knob, a Fusion gradient from the palette's Button colour.
   - The QLCDNumber bevel.
   - QCalendarWidget's red weekend numbers (a text format set in code).
4. A selected tree row is rounded per cell, so it shows a notch at each
   column. This was already true before. The palette fixes its own with
   `:first/:middle/:last` rules. It belongs with group c's one-hover-look
   item.
5. Corners are rounded only where Windows 11's compositor rounds them.
   Elsewhere, and offscreen, the combo list and the palette are square,
   while a QMenu keeps its 4 px sheet radius.
6. A combo row pads 8 px on each side. A menu item keeps its 25 px icon
   gutter. "Drawn as menu items" here means the same fill, radius,
   colours and vertical padding.
